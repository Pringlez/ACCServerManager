General Information

What is ACC Server Manager?

It is a modern web-based control panel designed to streamline Assetto Corsa Competizione (ACC) dedicated server orchestration. It allows simulation administrators to manage multiple server configurations, configure race weekend sessions, maintain entry lists, and deploy presets natively or in Docker containers.

Server Configurations

How does the application update game settings?

The InstanceDaoService reads and writes standard ACC JSON settings directly from/to the server configuration directories. This includes files such as settings.json, event.json, eventRules.json, entrylist.json, and assistRules.json.

Where can I read more about official server configuration parameters?

For a complete mapping of properties like track medals, weather randomness, and formation laps, please refer to the official ACC Dedicated Server Manual or standard community guides.

Docker Orchestration

How does Docker container integration work?

When the app is configured with the container control profile, ContainerControlService binds configuration directories on the physical host directly to the container's virtual workspace. It maps the game server ports dynamically and communicates directly with your host's Docker socket.

What Docker Java client library is utilized?

We utilize the enterprise-grade docker-java client library to handle socket bindings, commands, and containers. You can inspect its documentation on the official docker-java Repository .

Database Persistence

What relational databases are supported?

The application is equipped with full JPA support for two engines:
1. H2 Database: An extremely fast, local SQL database (can run completely in-memory or save to local filesystem), ideal for immediate local testing.
2. PostgreSQL: Fully compatible with standard production deployments by adjusting standard Spring DataSource credentials inside your environment properties.

How are users, roles, and event setups persisted?

Credentials, active tokens, roles (e.g. ADMIN, USER), and preconfigured track presets are persisted via standard SQL schemas mapped directly to tables such as USERS, ROLES, EVENT, and SESSIONS.
